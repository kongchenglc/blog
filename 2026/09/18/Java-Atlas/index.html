Java Atlas for Full-Stack Engineers

Fundamentals

Primitive Types vs Wrapper Types

Primitive types store raw values, while wrapper types are objects that can be null and are required by generics/collections.

== vs equals()

== compares primitive values or object references, while equals() compares object content when the class implements it accordingly.

hashCode()

hashCode() returns a hash value used by hash-based collections such as HashMap; objects that are equal according to equals() must return the same hash code.

String Immutability

Java String objects cannot be changed after creation; operations create a new string instead.

Exception Model

Java has checked exceptions, which must be caught or declared with throws, and unchecked exceptions, which may fail at runtime without explicit handling.

Checked exceptions represent expected external failures and must be handled or declared; unchecked exceptions usually indicate programming errors and may fail at runtime.

Generics

Generics let classes and methods work with different types while keeping compile-time type safety.

Optional

Optional<T> represents a value that may or may not exist, instead of directly using null.

Annotations

Annotations add metadata to classes, methods, or fields, and are heavily used by frameworks such as Spring to configure behavior.

record

A record is a concise way to define an immutable data carrier; Java automatically generates the constructor, accessors, equals(), hashCode(), and toString().

List, Set, Map

List stores ordered values, Set stores unique values, and Map stores key-value pairs.

ArrayList

ArrayList is the most common List implementation and is backed by a dynamically resizable array.

Compared with List:

  • List is the interface.
  • ArrayList is a concrete implementation.

HashMap

HashMap is the most common Map implementation for key-value storage and is not thread-safe.

Compared with Map:

  • Map is the interface.
  • HashMap is a concrete implementation.

ConcurrentHashMap

ConcurrentHashMap is a thread-safe Map implementation designed for concurrent access.

Compared with HashMap:

  • HashMap is not thread-safe.
  • ConcurrentHashMap safely supports concurrent access.
  • Compound operations can still have race conditions.

Stream API

The Stream API provides a functional, chainable way to transform and process collections, similar to JavaScript’s filter, map, and reduce.

Lambda Expressions

Java lambdas are anonymous functions, similar to JavaScript arrow functions.

Functional Interfaces

A functional interface gives a lambda a concrete Java type. It has exactly one abstract method, and the lambda provides that method’s implementation.

In practice, Java often uses built-in functional interfaces such as Function, Predicate, and Consumer.

Method References

Method references are shorthand for lambdas that only call an existing method.

User::isActive is equivalent to user -> user.isActive().

Java Runtime and Build System

JDK, JRE, and JVM

JDK provides Java development tools, JRE provides the runtime environment, and JVM executes compiled Java bytecode.

JDK = JRE + development tools, while JRE = JVM + runtime libraries.

Java Bytecode and javac

javac compiles Java source code into platform-independent bytecode, which is stored in .class files and executed by the JVM.

Concurrency Basics

Threads

A thread is an independent execution path inside a process. A Spring Boot application can handle multiple requests concurrently using multiple threads.

Thread Safety

Code is thread-safe when multiple threads can use it concurrently without corrupting shared state or producing incorrect results.

Race Conditions

A race condition happens when multiple threads read and modify the same shared state at the same time.

Two threads may both read the same old value:

The expected result is 2, but the actual result may be 1.

synchronized

synchronized allows only one thread at a time to execute a protected method or block for the same lock.

This prevents multiple threads from modifying the protected state at the same time.

Atomic Types

For simple atomic operations such as counters, Java provides classes such as AtomicInteger.

This is often simpler than manually using synchronized.

volatile

volatile guarantees visibility: when one thread updates a variable, other threads can see the latest value.

volatile does not make compound operations atomic.

Thread Pools

Creating a new thread for every task is expensive. A thread pool keeps reusable worker threads and assigns tasks to them.

ExecutorService

ExecutorService is Java’s high-level API for submitting work to a thread pool.

the executor manages and reuses worker threads.

Shared Mutable State

Shared mutable state is data that:

  1. can be changed, and
  2. can be accessed by multiple threads.

Shared mutable state is one of the main sources of concurrency bugs.

Prefer immutable data or method-local variables when possible.

Spring beans are singleton by default, so multiple HTTP requests may use the same bean instance concurrently.

JVM Basics

JVM Memory Model Overview

At runtime, the JVM manages several memory areas.

Stack vs Heap

Each thread has its own stack for method calls and local variables. The heap stores objects shared across the application.

Object Allocation

Objects created with new are generally allocated on the heap.

The local variable stores a reference to the object rather than the object itself.

Garbage Collection

Garbage Collection automatically reclaims heap memory from objects that are no longer reachable.

The old User object becomes eligible for garbage collection once nothing reachable refers to it.

Class Loading

Compiled .class files must be loaded into the JVM before they can be used.

Class loaders locate classes from classpath entries such as directories and JAR files.

Kafka Basics

Kafka is a distributed event-streaming platform commonly used for asynchronous communication, event-driven systems, and high-throughput data processing.

Producer / Consumer

A producer publishes messages.

A consumer reads and processes messages.

Topic

A topic is a named stream of messages.

Producers write to topics and consumers subscribe to them.

Partitions

A Kafka topic is split into partitions for scalability and parallel processing.

Each partition is an ordered log.

Kafka guarantees ordering within a partition, not across the entire topic.

When a message has a key, the producer typically uses that key to determine the partition.

Conceptually:

For example, if orderId is used as the key:

Messages with the same key normally go to the same partition, which preserves ordering for that key.

Without a key, messages can be distributed across partitions for better load balancing and throughput.

Consumer Groups

Consumers in the same consumer group share the work.

Within one consumer group, a partition is assigned to only one consumer at a time.

Different consumer groups can independently consume the same topic.

Offset

An offset represents a message’s position inside a partition.

Consumers track offsets to know how far they have processed.

At-Least-Once Delivery

A common Kafka delivery model is at least once, meaning a message may occasionally be processed more than once.

For example:

Therefore consumers should often be idempotent.

Idempotency

An operation is idempotent if processing the same event multiple times does not create incorrect duplicate effects.

Retry / Dead Letter Handling

Failed messages may be retried.

A dead-letter topic stores repeatedly failing messages for later inspection or reprocessing.

Kafka vs REST

REST is synchronous and request/response oriented:

Kafka is asynchronous and event oriented:

Use REST when an immediate response is needed.

Use Kafka when asynchronous processing, loose coupling, event distribution, or high throughput is useful.
